# yuuu-ui 0.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** yuuu-ui 0.5: a Tailwind entry point whose theme is the `--yuuu-*` tokens, the per-app override contract (accent family, neutral tint, shape, density), the new components yuuuTime needs, and the pragmatic AAA policy enforced by tests — without changing how 0.4's classes look.

**Architecture:** `public/css/yuuu-base.css` stays the hand-written, unlayered source of truth that Symfony apps link with no build. A new `public/css/tailwind.css` is what apps compiling Tailwind import after `@import "tailwindcss"`: it maps the tokens to a Tailwind v4 theme and pulls `yuuu-base.css` into the `components` layer, so utilities override components. No build step is added to yuuu-ui itself.

**Tech Stack:** plain CSS, PHP 8.4 + PHPUnit (the style tests), Node 22 + Vite + Tailwind v4 (`tailwindcss`, `@tailwindcss/vite`, only in the `tests/npm` fixture).

**Spec:** Part A of `C:\Users\ff_ze\.t3\worktrees\yuuu-time\t3-9545866d-8ec90400ebd611fc\docs\superpowers\specs\2026-11-23-visual-order-design.md` (yuuuTime repo, branch `feat/management-area`), decisions T-173, T-174, T-180 in `06-yuuutime-decisions.md` of the same repo.

**Refinement of the spec, to confirm with Kevin before Task 1.** The spec says the components are "rewritten on Tailwind". This plan keeps their CSS as it is and makes Tailwind the *theme and utility layer* instead. Reasons:
- **There is nothing to gain.** Every declaration already reads a token, so `@apply` would produce identical output.
- **The compiled file would be layered.** That changes the cascade for yuuuID, the CRM and the skeleton: their unlayered rules would start beating yuuu-ui's more specific ones.
- **yuuu-ui would gain a build step,** so committed output could drift from its source.

What T-173 asks for still holds: one system, the same class names, and utilities for layout wired to the tokens.

## Global Constraints

- Work in `D:\laragon-www\www\_wt-yuuu-ui-05`, branch `feat/0.5-tailwind` (based on `docs/pragmatic-aaa`, PR #2).
- Every class and token of 0.4.0 keeps its name and its declarations (README §10: they are public API).
- `yuuu-base.css` and `tokens.css`: no `@import`, no web fonts, no remote `url()`, no `@layer` (StylesheetHygieneTest). Works under CSP `style-src 'self'`.
- Defaults stay **sober** (style A): grey neutrals, today's radii and shadow. Warmth is an app's override, never a default.
- Accessibility (T-180), in both schemes: **AAA 7:1** for text that is read to work, **AA 4.5:1** for the pairs listed as secondary and for hover/press filters, **3:1** for non-text; anything tapped at least **44×44 px**; visible focus; no meaning by colour alone.
- Tailwind is **v4** (`tailwindcss@^4`, `@tailwindcss/vite@^4`), dev-only in the fixture; the shipped package keeps zero dependencies and no scripts.
- Gate: `bin/verify` (PHP: cs-fixer, PHPStan, PHPUnit) and `sh bin/verify-package` (npm), both green on every commit. Run PHP through the repo's usual way (`composer install` once; Docker `php:8.4-cli` if PHP is not on the host).
- Code, comments and docs in English. Every new public class is documented in README §5 (StylesheetHygieneTest fails otherwise).

## Review Focus

1. **An app that overrides a brand token with a colour that fails AAA**: the override contract is documented with the pairs it must meet. Task 2 adds a README worked example, and the yuuuTime overrides are checked by a test in yuuuTime (Part B).
2. **A Tailwind app that also links the compiled `yuuu-base.css`**: tokens are declared twice but the same, and the components layer still loses to utilities. Task 4's fixture page imports only `tailwind.css`. The README says not to link both.
3. **`prefers-color-scheme: dark` with `data-density="compact"` and a narrow screen together**: the side menu must not overflow horizontally and targets keep 44 px under `pointer: coarse`. Task 3 adds a hygiene assertion that compact control heights are inside `@media (pointer: fine)`.
4. **Tailwind's default palette leaking into apps** (`bg-teal-500` working and bypassing tokens): Task 4's fixture asserts that `bg-red-500` produces no CSS.
5. **The side menu with an `aria-current` link that is not visible on a phone**: on narrow screens the menu becomes a horizontal scrolling row and the current link scrolls into view. Task 3's README contract says so. It is checked by eye in Task 5's preview.
